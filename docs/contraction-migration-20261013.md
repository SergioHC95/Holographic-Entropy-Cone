# Contraction migration results on October 13 2026

The first staged migration implements rational count semantics,
proof-preserving canonicalization, independent exact verification, compact
full-map definitions, and immutable Git LFS shards. It does not yet replace
the published dataset or its public legacy reader.

## Verified hard case definitions

All 76 artifacts in the sealed `exact_order_kernel_v1` release passed fresh
compressed and decoded hash/size checks and exhaustive original-cube audits.
The migration extracted complete exact compatible seeds and created
independently verified `compatible-order-kernel/1` definitions.

| Measurement | Result |
| --- | ---: |
| Migrated hard-case proofs | 76 |
| Original compressed tables | 16,496,405,260 bytes |
| New authoritative compressed definitions | 35,364,916 bytes |
| Immutable proof shards | 3 |
| Reduction in authoritative proof payload | 99.7856 percent |
| Fresh original-source edges audited | 3,089,629,184 |
| Compatible seed edges independently checked | 16,660,467 |

The new functions prove the same primitive inequalities, with explicit
positive clearing scales. They are not labelled unscaled Boolean proofs and
need not reproduce every historical noncompatible output. Their definitions
are self-contained: neither evaluation nor mathematical acceptance needs
the old tables, seed-generating LP solver, caches, or production solver.

Original tables remain unchanged in the sealed archive. This reduces the
authoritative payload, not total local disk usage or historical server-side
LFS storage. Migration receipts bind original and target identities, scales,
hashes, audit scopes, and audit times.

## Verified ordinary proof pilot

All 14 existing n=1 through n=5 proofs were converted to canonical shared
scalar decision diagrams. They occupy 5,475 compressed bytes in one shard.
Fresh original-bit audits checked 8,465 edges. Exact symbolic verification
covers all edges of each new function. Original JSON files and normals were
copied into immutable hash-addressed archive snapshots.

Decision diagrams and kernel definitions share the same exact rational-count
mathematics and primary document format. Enumerated count tables have a
separate audit-export format and cannot enter an authoritative catalogue.

## Publication and remaining migration

A GitHub LFS upload negotiation for the three new hard-case shards returned
HTTP 403 on October 13: the repository exceeded its LFS budget. No proof
objects were uploaded, no active dataset pointers were changed, and no Git
history or old LFS objects were deleted.

The published 80,213-record n=6 base and the additional 4,387 original-scale
campaign maps still require their complete migration. Their proof strength,
party frames, facet/provenance distinctions, archive receipts, and original
cube audits must be preserved. The active reader, generation/export paths,
dataset checks, and CI asset selection must be cut over together after all
referenced new shards are available. No permanent legacy fallback is planned.

Production settings, completed proofs, and the sealed solver release were
not modified. No production or research search was started.
